Local HTTP API

Interface with python-front.py

Run the server, then send and retrieve JSON over HTTP. The default base URL is http://127.0.0.1:8080. Responses from API routes use JSON except for /health.

python3 python-front.py
curl http://127.0.0.1:8080/api/status

Endpoints

GET/health

Simple process health check. Returns plain text OK.

GET/api/status

Returns service status: {"status":"ok","service":"Situation"}.

POST/api/positions

Validates and appends one position report. Returns 201 Created with its database ID, or 400 with an error.

GET/api/positions

Returns the latest stored report for every device_id as {"positions":[...]}.

GET/api/positions/tails?seconds=300

Returns points received during the last 5–300 seconds. The query defaults to 300.

GET/api/tracks

Lists recorded runs with start time, end time, point count, and device count.

GET/api/tracks/<run_id>

Returns all stored positions for one URL-encoded run ID in timestamp order.

Submit a position

The example includes all required fields plus the optional status_text and activity_at fields. Status text may contain up to 500 characters. Activity time must be a timezone-aware ISO 8601 timestamp of at most 100 characters; it is used for target age and Live/Idle classification. Coordinates use WGS84 decimal degrees; heading is degrees, speed is km/h, and accuracy is metres.

curl -X POST http://127.0.0.1:8080/api/positions \
  -H 'Content-Type: application/json' \
  -d '{
    "run_id": "exercise-01",
    "device_id": "unit-alpha",
    "timestamp": "2026-07-17T12:00:00Z",
    "activity_at": "2026-07-17T12:00:00Z",
    "latitude": 49.6116,
    "longitude": 6.1319,
    "heading": 90,
    "speed": 8.0,
    "accuracy": 5.0,
    "sidc": "SFGPUCI----K---",
    "designation": "Alpha",
    "status_text": "En route"
      }'
Identity: Reuse a stable device_id to move the same map symbol. Use run_id to group reports into a retrievable track.
Time semantics: timestamp describes the position fix, optional activity_at describes the source's latest observed activity, and response field received_at records when Situation accepted the report. Age prefers these fields in the order activity_at, received_at, then timestamp.

Included clients

python-simulator.py

Posts three moving demonstration units once per second. It runs until stopped unless --steps is set.

python3 python-simulator.py
python3 python-simulator.py --steps 10 --interval 0.5
python3 python-simulator.py --url http://server:8080/api/positions \
  --run-id exercise-01

--interval minimum 0.1 s · --steps 0 runs forever · --run-id defaults to a UUID

tak-bridge.py

Receive-only adapter that connects to taky-ng as an ordinary TAK client, accepts current CoT atom positions, normalizes them, and posts them to this API.

python3 tak-bridge.py
python3 tak-bridge.py --host 192.0.2.10 --port 8087 \
  --url http://127.0.0.1:8080/api/positions

Defaults: plain CoT TCP on 127.0.0.1:8087 · reconnect after 3 s · summary event logging

The current bridge uses an unencrypted plain TCP listener. Keep it on a trusted network; TAK protocol and certificate handling remain outside python-front.py.

Server options

python3 python-front.py \
  --listen 127.0.0.1 \
  --port 8080 \
  --web-dir ./web \
  --map-dir ./maps \
  --database ./situation.db

API requests are limited to 64 KiB. Data is appended to SQLite; no authentication is provided by the Python server, so use a trusted interface or a properly configured reverse proxy.
